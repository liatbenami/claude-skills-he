## 1. מספרים שמתהפכים על המסך

**התסמין:** כתוב בקוד `16:00 – 19:30`, ועל המסך מופיע `19:30 – 16:00`. אף אחד לא נגע בטקסט.

**למה:** אלגוריתם הדו-כיווניות של יוניקוד מסווג מספרים כ"ניטרליים חלשים". בתוך פסקה עברית הם מסתדרים מימין לשמאל, ולכן שני מספרים משני צדי מקף מחליפים מקום.

**התיקון:** בידוד כיווניות על האלמנט.

```html
<div class="fact-value" dir="ltr">16:00 – 19:30</div>
<input type="tel" dir="ltr" style="text-align: right;">
```

**על מה זה חל:** טווחי שעות, טווחי תאריכים, מספרי טלפון, כתובות אימייל, כתובות אתרים, מחירים עם מטבע לטיני, מספרי בית. **לא** חל על מספר בודד בתוך משפט (`350 ₪` תקין, כי אין שני מספרים שיכולים להחליף מקום).

בשדה קלט `dir="ltr"` לבדו יצמיד את הטקסט שמאלה, ולכן מוסיפים `text-align: right` כדי שוויזואלית הוא יישאר מיושר עם שאר הטופס.

## 2. כותרת דביקה שבולעת תוכן

**התסמין:** לחיצה על קישור עוגן (`#register`) קופצת לסקשן, אבל שורת הכותרת שלו מוסתרת מאחורי ההדר.

**למה:** `position: sticky` מוציא את ההדר מזרימת המסמך. הדפדפן גולל כך שראש הסקשן יהיה בראש החלון — בדיוק מתחת למקום שבו ההדר יושב.

**התיקון:**

```css
section[id] {
  scroll-margin-top: 140px;   /* גובה ההדר + מרווח נשימה */
}
```

**לשים לב:** ההדר גבוה יותר בנייד מאשר בדסקטופ (הטקסט נשבר, הלוגו בשורה אחרת). מדדי את הגובה האמיתי בנייד, לא בדסקטופ.

## 3. טקסט שנשבר לשתי שורות

**התסמין:** כותרת משנה או טקסט כפתור נשברים בנייד, ומילה אחת או אמוג'י נשארים לבד בשורה שנייה. נראה שבור.

**התיקון:** איסור שבירה, בשילוב פונט שמתכווץ לפי רוחב המסך.

```css
.hero-subtitle {
  white-space: nowrap;
  font-size: clamp(.78rem, 3.5vw, 1.4rem);
}
```

`clamp(מינימום, רצוי, מקסימום)` — הערך האמצעי ב-`vw` גדל וקטן עם רוחב החלון, ושני הקצוות מונעים ממנו להיות זעיר או ענק.

**איך לבחור את מקדם ה-vw:** אל תנחשי. מדדי את הרוחב הזמין ואת הרוחב שהטקסט תופס, וחשבי. ב-Playwright:

```js
const el = document.querySelector('.hero-subtitle');
const avail = el.getBoundingClientRect().width;
let max = null;
for (let px = 8; px <= 28; px += 0.5) {
  el.style.fontSize = px + 'px';
  if (el.scrollWidth <= avail) max = px;
}
// max / רוחב-החלון * 100 = מקדם ה-vw
```

בפרויקט נושמות לידה זה היה ההבדל בין פונט 9.4px (קטן מכדי לקרוא) ל-12.5px — ובכלל לא בגלל הפונט, אלא כי הריפוד של ההדר אכל את הרוחב. **קודם בדקי אם אפשר להרוויח רוחב** (ריפוד, מרווחים, לוגו קטן יותר) ורק אחר כך הקטיני פונט.

## 4. שדות טופס קטנים מדי לאצבע

יעד מגע מתחת ל-44px גורם להחטאות. קל ליפול לזה כשמצמצמים טופס שנראה "מרווח מדי" בדסקטופ.

**הפתרון: לא להתפשר על אחד מהם.** טופס דחוס בדסקטופ, מרווח בנייד:

```css
.form-control { padding: 10px 14px; }        /* דסקטופ - דחוס */

@media (max-width: 768px) {
  .form-control { padding: 13px 14px; }      /* נייד - 48px גובה */
  summary, .small-button { padding: 11px 0; }
}
```

## 5. iOS שמזים את העמוד

**התסמין:** באייפון, לחיצה על שדה טופס מגדילה את כל העמוד ומשאירה אותו מוזח.

**למה:** ספארי מזים אוטומטית לכל שדה קלט שהפונט בו קטן מ-16px.

**התיקון:**

```css
@media (max-width: 768px) {
  .form-control,
  .form-control::placeholder { font-size: 16px; }
}
```

16px בדיוק. לא 15.5.

## 6. margin ימין ושמאל

ב-RTL `margin-right` לא אומר "לפני המילה" — הוא אומר "בצד ימין", וזה מתהפך אם הדף יתורגם אי פעם.

```css
.host-name {
  margin-inline-start: 3px;   /* הצד שממנו מתחילה הקריאה - ימין בעברית */
}
```

**והערה על מינון:** רווח של 7px ועוד 4px ריפוד נראה בקוד כמו "קצת אוויר" ועל המסך כמו ניתוק. התחילי מ-**3px** והגדילי רק אם באמת צריך.

## 7. כשל שקט בהעתקה ללוח

`navigator.clipboard` קיים רק ב-HTTPS או ב-localhost. אם מישהי פותחת את הקובץ ישירות (`file://`), הכפתור לא עושה כלום ולא מציג שום שגיאה.

```js
if (navigator.clipboard && window.isSecureContext) {
  navigator.clipboard.writeText(text)
    .then(() => show("הועתק ✓"))
    .catch(() => selectInstead());
} else {
  selectInstead();   /* מסמנים את הטקסט על המסך להעתקה ידנית */
}
```

**הכלל הרחב:** כל `.then()` צריך `.catch()`. כשל שקט הוא הגרוע מכולם — הוא נראה תקין בקוד ושבור אצל המשתמשת.

## 8. בדיקה שתופסת את כולם

אם יש Playwright, זו בדיקה אחת שמחזירה את רוב הבעיות:

```js
() => {
  const vw = document.documentElement.clientWidth;
  const over = [];
  document.querySelectorAll('*').forEach(el => {
    const b = el.getBoundingClientRect();
    if (b.width > 0 && (b.right > vw + 1 || b.left < -1)) {
      over.push(el.tagName + '.' + (el.className || '').toString().slice(0, 25));
    }
  });
  return {
    viewport: vw,
    horizontalScroll: document.documentElement.scrollWidth > vw,
    overflowing: [...new Set(over)].slice(0, 8),
    inputHeight: document.querySelector('.form-control')?.getBoundingClientRect().height,
    inputFont: getComputedStyle(document.querySelector('.form-control') || document.body).fontSize
  };
}
```

הריצי ב-390px וב-320px. `horizontalScroll: false` ו-`overflowing: []` הם התנאי לדף תקין בנייד.

**ולבדיקת היפוך מספרים** — מדידת המיקום האופקי של כל תו, שמראה מה באמת מופיע על המסך:

```js
() => {
  const node = document.querySelector('.fact-value').firstChild;
  const r = document.createRange();
  const parts = [];
  for (let i = 0; i < node.length; i++) {
    r.setStart(node, i); r.setEnd(node, i + 1);
    parts.push([r.getBoundingClientRect().left, node.data[i]]);
  }
  return parts.sort((a, b) => a[0] - b[0]).map(p => p[1]).join('');
}
```
