## מה לערוך

רק שני הבלוקים בראש הקובץ. כל השאר כללי.

```js
var CFG = {
  sheetId:  'PASTE_SHEET_ID',        // מתוך כתובת הגיליון, בין /d/ ל-/edit
  mainName: 'נרשמות',                 // שם הגיליון הראשי
  waitName: 'רשימת המתנה',            // ייווצר לבד כשיהיה צורך
  capacity: 15,                       // 0 = בלי הגבלה
  notify:   'manager@example.com',    // התראות. אפשר כמה, מופרדים בפסיק
  replyTo:  'manager@example.com',    // כתובת אחת בלבד!
  tz:       'Asia/Jerusalem'
};

var EVENT = {
  name, date, hours, place, parking, price, includes,
  payLink, bitPhone, waPhone, site
};
```

**`notify` מול `replyTo`** — שתי הגדרות שנראות דומות ואסור לאחד:
`notify` יכול להיות רשימה, כי זו סתם שליחה לכמה נמענים. `replyTo` חייב כתובת **אחת** — זה מה שקורה כשנרשמת לוחצת "השב", ורשימה שם או נשברת או שולחת את תשובתה לכמה אנשים.

**שדה ריק ב-`EVENT` פשוט לא מוצג.** `parking: ''` לא ייצור שורה ריקה במייל, ו-`payLink: ''` יחליף את כפתור התשלום בתצוגה של מספר הביט. אפשר להשאיר ריק בלי לגעת בקוד.

## זרימת ההרשמה

```
doPost
  ├── שדות חובה חסרים?  ──▶  {ok:false, error:'missing_fields'}
  ├── יש מקום?
  │     כן ──▶ רישום בגיליון הראשי ──▶ מייל עם קישור תשלום ──▶ {ok:true, waitlist:false}
  │     לא ──▶ רישום ברשימת המתנה  ──▶ מייל בלי תשלום      ──▶ {ok:true, waitlist:true, position:N}
  └── חריגה ──▶ רישום ביומן ──▶ {ok:false, error:'server_error'}
```

בדיקת שדות החובה קיימת גם בשרת וגם בדפדפן בכוונה. ולידציה בדפדפן היא נוחות למשתמשת; רק בדיקת השרת באמת מגינה, כי אפשר לשלוח בקשה ישירות בלי לעבור דרך הדף.

## ספירת תפוסה

```js
function activeCount(sheet) {
  var rows = sheet.getLastRow() - 1;
  if (rows < 1) return 0;
  var status = sheet.getRange(2, 6, rows, 1).getValues();
  var n = 0;
  for (var i = 0; i < rows; i++) {
    if (String(status[i][0]).trim() !== 'בוטל') n++;
  }
  return n;
}
```

**הספירה מתעלמת מ"בוטל", ולא סופרת שורות.** זה מה שהופך ביטול לפינוי מקום אמיתי. אילו ספרנו שורות, האירוע היה נשאר "מלא" לנצח גם אחרי שחצי ביטלו — והדרך היחידה לפנות מקום הייתה למחוק שורות ולאבד את ההיסטוריה.

העמודה הנספרת היא F (עמודה 6), "סטטוס תשלום". אם את משנה את סדר העמודות, עדכני את המספר **בשתי** הפונקציות: `activeCount` ו-`firstWaitingRow`.

## רשימת המתנה

הגיליון נוצר רק כשהנרשמת הראשונה בתור מגיעה. זו בחירה מכוונת — גיליון ריק שיושב שם חודשיים רק מבלבל את מי שפותחת את הקובץ.

`checkWaitlist` רצה בטריגר שעתי:

```
כל עוד יש מקום פנוי ויש מישהי בתור:
    להעתיק את השורה הראשונה לגיליון הראשי
    לסמן "עלתה מרשימת ההמתנה" בהערות
    למחוק אותה מרשימת ההמתנה
    לשלוח לה מייל עם קישור תשלום
```

הלולאה מטפלת גם במקרה שהתפנו כמה מקומות בבת אחת, ואז נשלחת למנהלת הודעת סיכום אחת במקום הצפה.

**בלי הטריגר רשימת ההמתנה רק נרשמת ולא מתקדמת.** זה שלב נפרד בהתקנה — ראי `deploy.md`.

## המיילים

שלושה סוגים על מעטפת עיצוב אחת (`shell`), כדי שכולם ייראו כמו אותו מותג:

| פונקציה | מתי | קישור תשלום |
|---|---|---|
| `confirmRegistered` | נרשמה ויש מקום | ✅ |
| `confirmWaitlist` | האירוע מלא | ❌ בכוונה |
| `confirmPromoted` | התפנה מקום ועלתה | ✅ |

**למה מייל ההמתנה בלי תשלום:** אישה שתשלם בזמן שהיא בתור תחשוב שיש לה מקום. אחר כך מישהי תצטרך להחזיר לה כסף ולהסביר. השקט הזה בשלב ההמתנה הוא החלטה, לא השמטה.

כל שליחת מייל עטופה ב-`try/catch` נפרד:

```js
try {
  MailApp.sendEmail({ ... });
} catch (err) {
  console.error('mail to ' + to + ' failed: ' + err);
}
```

**כישלון בחיווי לא אמור להפיל רישום.** ההרשמה כבר נשמרה בגיליון; אם המכסה היומית נגמרה או הכתובת שגויה, עדיף שהמייל ייכשל בשקט ויירשם ביומן מאשר שכל הבקשה תחזיר שגיאה והאישה תחשוב שלא נרשמה.

## החלטות שכדאי להכיר

**גרש לפני הטלפון**

```js
"'" + String(p.phone).trim()
```

בלעדיו גוגל ממירה `0501234567` למספר ומוחקת את ה-0. הגרש מכריח התייחסות כטקסט ולא מוצג בתא.

**`openById` ולא `getActiveSpreadsheet`**

`getActiveSpreadsheet` עובד רק בסקריפט שנוצר מתוך תפריט הגיליון. `openById` עובד בשניהם, ולכן אפשר להקים הכל מ-`script.google.com` בלי לחפש תפריטים.

**`ContentService` ולא `HtmlService`**

התשובה היא JSON שהדפדפן קורא, לא עמוד.

## שינויים נפוצים

**להוסיף שדה לטופס** — שלושה מקומות: ה-HTML, אובייקט `data` ב-JS של הדף, ו-`appendRegistration` בקוד. להוסיף גם ל-`HEADERS` ולעדכן את רוחבי העמודות.

**לשנות את מספר העמודות** — לעדכן את `HEADERS`, את מערך הרוחבים ב-`sheetByName`, ואת מספר עמודת הסטטוס ב-`activeCount` וב-`firstWaitingRow`.

**לבטל את הגבלת התפוסה** — `capacity: 0`. רשימת ההמתנה לא תיווצר לעולם.

**לחסום אימייל כפול** — ב-`doPost`, לפני הרישום:

```js
var emails = main.getLastRow() > 1
  ? main.getRange(2, 4, main.getLastRow() - 1, 1).getValues().map(function (r) {
      return String(r[0]).trim().toLowerCase();
    })
  : [];
if (emails.indexOf(String(p.email).trim().toLowerCase()) > -1) {
  return json({ ok: false, error: 'duplicate' });
}
```

ואז לטפל ב-`duplicate` גם בדף, עם הודעה בעברית. **זו החלטה עסקית** — יש מנחות שמעדיפות לקבל, כי לפעמים אישה רושמת גם חברה. לשאול לפני.

**לבדוק אחרי כל שינוי**

```
node scripts/test_logic.js assets/Code.gs
```
