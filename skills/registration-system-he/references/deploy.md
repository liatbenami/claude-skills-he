## ההוראות עצמן

> **1.** פתחי [script.google.com/home](https://script.google.com/home) ולחצי **פרויקט חדש** / *New project*
>
> **2.** סמני הכל במסך הקוד (Ctrl+A), מחקי, והדביקי את הקוד ששלחתי → **Ctrl+S**
>
> **3.** לחצי **פריסה** / *Deploy* (כפתור כחול מימין למעלה) → **פריסה חדשה** / *New deployment*
>
> **4.** ליד "בחירת סוג" יש **גלגל שיניים ⚙️** → לחצי עליו → בחרי **אפליקציית אינטרנט** / *Web app*
>
> **5.** מלאי שני שדות:
> - **הפעלה בתור** / *Execute as* → **אני** / *Me*
> - **למי יש גישה** / *Who has access* → **כל אחד** / **Anyone**
>   ⚠️ ברירת המחדל היא "רק אני" וזה יחסום את כל הנרשמות
>
> **6.** לחצי **פריסה** / *Deploy*
>
> **7.** גוגל תציג אזהרה — זה נורמלי, זה הסקריפט שלך בחשבון שלך:
> **בדיקת הרשאות** / *Review permissions* → בחרי את החשבון → **מתקדם** / *Advanced* (קישור קטן למטה) → **מעבר אל...** / *Go to… (unsafe)* → **אישור** / *Allow*
>
> **8.** העתיקי את **כתובת אתר של אפליקציית אינטרנט** / *Web app URL* ושלחי לי אותה.
> ⚠️ הכתובת צריכה להסתיים ב-**`/exec`**. אם היא מסתיימת ב-`/dev` זו כתובת בדיקה, לא האמיתית.

## לעדכן קוד קיים

זה השלב שהכי הרבה נופלים בו. **`Ctrl+S` שומר את הקוד אבל לא מעדכן את מה שרץ באוויר.**

> **1.** הדביקי את הקוד החדש → **Ctrl+S**
> **2.** **פריסה** / *Deploy* → **ניהול פריסות** / *Manage deployments*
> **3.** **✏️ עיפרון** (עריכה)
> **4.** ← **השלב הקריטי:** בשדה **גרסה** / *Version* בחרי **גרסה חדשה** / **New version**
>     אם הוא נשאר על "גרסה 1", נפרסת שוב בדיוק את אותו קוד ישן
> **5.** **פריסה** / *Deploy*

הכתובת לא משתנה בעדכון. אם קיבלת כתובת חדשה — יצרת פריסה חדשה במקום לערוך את הקיימת, והישנה עדיין חיה במקביל.

**איך לוודא שהעדכון באמת נכנס:** לבדוק את **מבנה** התשובה, לא רק אם היא תקינה. כששינית משהו שמשפיע על ה-JSON (הוספת שדה, שינוי שם), שלחי בקשת בדיקה ובדקי שהשדה החדש חוזר. `ok:true` חוזר גם מהגרסה הישנה ולכן לא מעיד על כלום.

## לפענח את התשובה

| מה חוזר | מה זה אומר | מה לעשות |
|---|---|---|
| `{"ok":true,"waitlist":false}` | נרשמה בהצלחה | — |
| `{"ok":true,"waitlist":true,"position":N}` | האירוע מלא, נכנסה לתור | — |
| `{"ok":false,"error":"missing_fields"}` | חסרו שם/טלפון/אימייל | תקין — ככה זה אמור להתנהג |
| `{"ok":false,"error":"server_error"}` | חריגה בקוד | לבקש ממנה לפתוח **ביצועים** / *Executions* בעורך ולשלוח את השגיאה |
| **HTTP 401** + "לא ניתן לפתוח את הקובץ" | ההרשאה אינה "כל אחד" | לחזור לשלב 5 בהוראות |
| **HTTP 404** | הכתובת שגויה או שהפריסה נמחקה | לוודא שהכתובת נגמרת ב-`/exec` |
| **HTTP 411** | תקלה בכלי הבדיקה, לא בשרת | `curl` עם `-L` ו-`-X POST` שולח מחדש בלי Content-Length. להשמיט `-X POST` |
| HTML של מסך התחברות | אותה בעיה כמו 401 | לתקן את ההרשאה |

## טריגר רשימת ההמתנה

בלי זה רשימת ההמתנה לא מתקדמת לבד — היא רק נרשמת.

> בעורך הסקריפט, בתפריט הצר בצד שמאל, לחצי על **⏰ שעון** (*Triggers*) → **הוספת טריגר** / *Add Trigger* →
> - פונקציה: **`checkWaitlist`**
> - מקור האירוע: **מבוסס זמן** / *Time-driven*
> - סוג: **טיימר שעתי** / *Hour timer*
>
> → **שמירה**

**להרצה ידנית מיידית** (למשל לבדיקה): בסרגל שמעל הקוד יש תפריט נפתח עם שם פונקציה. בחרי בו **`checkWaitlist`** ולחצי **▶ הפעלה** / *Run*. התוצאה תופיע ב**יומן ביצוע** / *Execution log* בתחתית.

## תקלות נפוצות

**"אין לי תפריט תוספים בגיליון"** — או שהיא בטלפון (Apps Script לא קיים באפליקציה, חייבים מחשב), או שהחלון צר והתפריטים התכנסו לכפתור `⋯`. בכל מקרה הדרך דרך `script.google.com` עוקפת את זה. הקוד משתמש ב-`openById` ולכן עובד גם בסקריפט עצמאי שאינו מחובר לגיליון.

**"התפריט הנפתח של הפונקציות ריק או אפור"** — הקוד לא נשמר. Ctrl+S.

**עברית שמגיעה כ-`?????` בגיליון** — כמעט תמיד הכלי ששלח את הבקשה, לא השרת. דפדפנים שולחים UTF-8 תמיד. `scripts/test_endpoint.py` שולח UTF-8 תקין; אם דרכו העברית נכנסת נכון, אין בעיה.

**טלפון שמאבד את ה-0 המוביל** — גוגל ממירה `0501234567` למספר. הקוד מוסיף גרש (`'`) לפני הערך, וזה מכריח את הגיליון להתייחס אליו כטקסט.

**מכסת מיילים** — חשבון Gmail רגיל מוגבל ל-100 נמענים ביום דרך Apps Script. לאירוע של עשרות משתתפות זה לא רלוונטי; אם מדובר במאות, צריך לומר לה את זה מראש.
