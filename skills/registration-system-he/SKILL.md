# מערכת הרשמות

מטרת הסקיל: שטופס באתר סטטי יישמר במקום אמיתי, שהנרשמת תקבל אישור, ושאף הרשמה לא תיעלם. הכל על תשתית חינמית של גוגל, בלי שרת.

## הארכיטקטורה — ולמה היא כזו

```
דף HTML סטטי  ──fetch──▶  Google Apps Script  ──▶  Google Sheet
                                   │
                                   └──▶  מיילים (לנרשמת ולמנהלת)
```

**למה בכלל צריך את החוליה האמצעית:** דף סטטי לא יכול לכתוב לגוגל-שיט ישירות, כי זה דורש מפתח הרשאה — ומפתח בקוד של אתר ציבורי גלוי לכל מי שלוחץ "הצג מקור". Apps Script מחזיק את ההרשאה בצד השרת ורץ בשם בעלת החשבון.

**למה דווקא Apps Script ולא Formspree/Supabase/Netlify:** כולם דורשים פתיחת חשבון בשירות נוסף. Apps Script כבר קיים בחשבון הגוגל שיש לה ממילא, חינמי, ומחובר לגיליון שהיא כבר יודעת לקרוא.

## מגבלה שחייבים לומר לה מראש

**את לא יכולה להקים את זה בשבילה.** Apps Script יושב בתוך חשבון הגוגל שלה, ואין לך אליו גישה. התפקיד שלך הוא לכתוב את הקוד, לנסח הוראות מדויקות, ולבדוק מבחוץ שזה עובד. ההדבקה והפריסה הן שלה — כ-5 דקות.

אמרי לה את זה בהתחלה, בפירוש. אחרת היא תחכה שתסיימי, ותתוסכל כשתתברר שצריך ממנה משהו.

## התהליך

### 1. הגיליון

אם יש חיבור ל-Google Drive/Sheets — צרי אותו בעצמך. אחרת בקשי ממנה ליצור גיליון ריק ולשלוח את הקישור.

מזהה הגיליון נמצא בתוך הכתובת:
`docs.google.com/spreadsheets/d/`**`זה_המזהה`**`/edit`

הסקריפט יוצר את הכותרות והעיצוב לבד בהרצה הראשונה, אז אין צורך להכין כלום בגיליון.

### 2. הסקריפט

העתיקי את `assets/Code.gs` לתיקיית הפרויקט ועדכני **רק את בלוק `CFG` בראש הקובץ**. כל השאר כללי.

```js
var CFG = {
  sheetId:  'מזהה הגיליון',
  capacity: 15,                          // 0 = בלי הגבלה
  notify:   'מנהלת@gmail.com',           // אפשר כמה, מופרדים בפסיק
  replyTo:  'מנהלת@gmail.com',           // כתובת אחת בלבד
};
```

`references/apps-script.md` מסביר כל חלק בקוד ומה בטוח לשנות.

### 3. ההוראות לפריסה

אל תכתבי אותן מחדש. `references/deploy.md` הוא טקסט מוכן בעברית, עם תוויות הממשק בשתי השפות — הממשק של Apps Script מתורגם רק חלקית ומבלבל. שלחי לה אותו כמו שהוא.

בסוף היא תשלח לך כתובת שנגמרת ב-`/exec`. הדביקי אותה בקבוע `SCRIPT_URL` בדף.

### 4. חיבור הטופס

`references/frontend.md` מכיל את קוד הצד-לקוח: שליחה בלי לעזוב את העמוד, ולידציה בעברית, פאנל אישור, ורשת ביטחון לוואטסאפ אם השרת נופל.

### 5. הבדיקה

```
python scripts/test_endpoint.py <כתובת ה-exec>
```

הסקריפט בודק שדות חסרים, הרשמה תקינה, ועברית ב-UTF-8, ומסביר כל תשובה. ראי `references/deploy.md` → "לפענח את התשובה" כדי להבין מה אומר כל קוד שגיאה.

## שלוש מלכודות שיעלו לך זמן אם לא תכירי אותן

**פריסה שלא נכנסה לתוקף.** `Ctrl+S` שומר את הקוד אבל לא מעדכן את מה שרץ באוויר, וגם "פריסה מחדש" בלי לבחור **גרסה חדשה** פורסת שוב את אותו קוד ישן. הדרך לדעת בוודאות: **לבדוק את מבנה התשובה, לא רק אם היא תקינה.** אם הוספת שדה חדש ל-JSON והוא לא חוזר — הגרסה הישנה עדיין באוויר.

**401 מהשרת.** פירושו שההרשאה "למי יש גישה" אינה **כל אחד**. ברירת המחדל של גוגל היא "רק אני", וזה חוסם את כל הנרשמות.

**עברית שנשמרת כסימני שאלה.** כמעט תמיד זו תקלה בכלי הבדיקה (curl בווינדוס), לא בשרת. דפדפנים שולחים UTF-8 תמיד. `scripts/test_endpoint.py` שולח UTF-8 נכון ולכן מבדיל בין השניים.

## לבדוק תפוסה ורשימת המתנה בלי 15 הרשמות מזויפות

צרי עותק זמני של הסקריפט עם `capacity: 2` ועם `notify` שמכוון אלייך, פרסי אותו, בדקי, והחזירי את הגרסה האמיתית.

שימי לב לשתיים:

- **כתובות עם `+`** — `שם+test1@gmail.com` מגיע לאותה תיבה. כך בודקים שלוש "נרשמות שונות" ורואים את כל המיילים בעיניים, בלי תיבות דואר מזויפות.
- **הסיכון האמיתי הוא לשכוח להחזיר.** אם גרסת הבדיקה נשארת פרוסה, הנרשמת השלישית האמיתית תיכנס לרשימת המתנה בטעות. סמני את זה כמשימה פתוחה והזכירי בסוף.

## שתי החלטות שהיא צריכה לקבל, לא את

**מה קורה עם אימייל כפול.** לדחות ("כבר נרשמת") או לקבל כהרשמה נוספת, כי אולי היא רושמת חברה? ברירת המחדל בקוד מקבלת ומסמנת בהערה.

**איפה מתבצע התשלום.** כפתור באתר נוח, אבל מאפשר לשלם בלי להירשם — ובפרט כשהאירוע מלא. כפתור במייל שאחרי ההרשמה סוגר את זה: רק מי שהמערכת שיבצה מקבלת את הקישור. ברירת המחדל בקוד היא במייל.

הציגי לה את הטרייד-אוף בשתי שורות ותני לה לבחור. אלה החלטות עסקיות, לא טכניות.
